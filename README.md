# 前端开发 Mock 接口生成工具

## 这是什么？

一个用 Cursor + AI 自动生成 Mock 接口的本地服务器。

**解决的问题**：前端开发时，只有接口文档但后端还没开发完，需要可调用的接口来做开发和测试。

**和其他方案的区别**：
- ❌ 手写 Mock 数据 → 费时费力
- ❌ 使用 Mock.js → 数据格式死板，要写代码
- ❌ 使用 Apifox/Postman Mock → 需要手动配置，数据不够真实，对文档格式有要求
- ✅ **本工具** → 给 Cursor 一个接口文档，AI 自动生成可运行的真实接口（带数据库、可增删改查）

## 使用场景

**前端开发**：有接口文档，但还无法联调

## 核心优势

- ✅ **真实接口**：不是假数据，是真的 HTTP 接口
- ✅ **带数据库**：数据可以增删改查，不是固定的
- ✅ **自动生成**：不用手写代码，告诉 AI 就行
- ✅ **即用即删**：用完删除，不影响其他部分
- ✅ **后台管理**：可以修改数据、测试接口、模拟各种场景

## 使用条件

**必须条件**：
1. ✅ **Cursor 编辑器** - 项目依赖 Cursor 的 AI 能力来生成接口
2. ✅ **MySQL 数据库** - 生成的接口需要数据库存储数据
3. ✅ **Node.js 18+** - 运行服务器

**为什么必须用 Cursor？**
- 本项目是给 Cursor 用的，AI 需要读取项目的规则文档和模板来生成接口
- 生成的接口质量很高，基本上不用改就能用
- 如果不用 Cursor，就失去了这个工具的意义（变成手写代码了）

## 快速开始

### 1. 安装环境

```bash
# 确保已安装 Node.js 18+ 和 MySQL 8+
node -v  # 应该显示 v18.x.x 或更高
mysql --version  # 应该显示 8.x.x 或更高
```

### 2. 克隆并启动项目

```bash
# 克隆项目
git clone <repository-url>
cd node-api-server

# 安装依赖
npm install

# 配置数据库（复制 .env.example 改成 .env，然后修改里面的数据库配置）
cp .env.example .env
# 编辑 .env 文件，填写你的 MySQL 信息

# 初始化数据库
npm run db:init

# 启动服务（开发模式，支持热重载）
npm run dev
```

### 3. 访问后台

打开浏览器：`http://localhost:8088/admin`

你会看到管理后台，可以查看模块、管理数据、测试接口等。

### 4. 用 Cursor 生成接口

**重要**：必须用 Cursor 打开这个项目！

在 Cursor 的聊天框里输入：

```
我有一个用户管理的接口文档，帮我生成对应的接口模块：

接口列表：
1. GET /api/users - 获取用户列表（分页）
2. GET /api/users/:id - 获取用户详情
3. POST /api/users - 创建用户
4. PUT /api/users/:id - 更新用户
5. DELETE /api/users/:id - 删除用户

字段：
- id: 用户ID（主键）
- username: 用户名
- email: 邮箱
- phone: 手机号
- status: 状态（0-禁用 1-启用）
- created_at: 创建时间

响应格式用 B2B 格式。
```

**关于响应格式说明**：

本项目内置了 **B2B**、**ERP** 和 **Ebooking** 三种响应格式，因为这是我常用的格式：

- **B2B/Ebooking 格式**：`{ success: true, code: 0, message: "", data: {} }`（code 为 0 表示成功）
- **ERP 格式**：`{ Success: true, Code: 0, Message: "", Data: {} }`（大写字段，Code 为 0 表示成功）

如果你的项目用的是其他格式（比如标准 REST、GraphQL 等），可以让 AI 添加。

**添加自定义响应格式的提示词模板**：

```
我需要添加一个新的响应格式 [格式名称]，用于我的项目。

响应格式示例：
成功时：
{
  "status": "ok",
  "result": {...},
  "error": null
}

失败时：
{
  "status": "error",
  "result": null,
  "error": {
    "code": "ERROR_CODE",
    "message": "错误信息"
  }
}

请修改 src/core/Response.ts 文件，添加这个新格式的支持：
1. 在 ResponseFormat 类型中添加新格式
2. 在 buildResponse 方法中添加对应的处理逻辑
3. 确保成功和失败时的字段结构符合上面的示例

修改完成后，我就可以在生成接口时使用这个格式了：
响应格式用 [格式名称] 格式。
```

**使用方法**：
1. 复制上面的模板
2. 把 `[格式名称]` 改成你的格式名（比如 `Standard`、`GraphQL` 等）
3. 把示例中的 JSON 结构改成你需要的格式
4. 粘贴给 Cursor，AI 会自动修改代码

AI 会自动：
1. 在 `src/generated/users/` 下生成完整的模块代码
2. 创建数据库表
3. 生成一些测试数据
4. 接口立即可用

然后你就可以在前端调用这些接口了：
```javascript
// 获取用户列表
fetch('http://localhost:8088/api/users')
  .then(res => res.json())
  .then(data => console.log(data))
```

## 实际使用流程

### 第一步：准备文档并生成接口

将接口文档或需求文档粘贴到 Cursor 聊天框，告诉 AI 生成接口。

### 第二步：前端开发

生成的接口立即可用，直接在前端代码里调用就行。

### 第三步：测试和调整

- 用后台管理页面查看/修改数据
- 测试各种场景（网络慢、接口报错等）
- 需要改接口？再告诉 Cursor 修改就行

### 第四步：后端完成后切换

后端接口开发完成后，前端只需要改一下接口地址（或者改代理配置），其他代码不用动。

因为你用的是真实接口，数据结构也是真实的，所以切换过去基本不会有问题。

## 后台功能说明

访问 `http://localhost:8088/admin` 可以使用这些功能：

### 1. 模块管理
- 查看已生成的所有接口模块
- 删除模块（会同时删除数据库表和数据）

**注意**：不要手动删除 `src/generated/` 下的文件夹，用后台删除功能，会自动清理数据库。

### 2. 数据管理
- 查看所有数据表的数据
- 新增/修改/删除数据（可以直接点击表格单元格编辑）
- 生成测试数据（AI 会根据字段名自动生成合理的数据）
- 清空数据

### 3. 接口管理
- 查看所有接口
- 为接口设置场景（模拟延迟、错误等）

### 4. 场景管理
- 理想环境：接口正常响应
- 网络慢：延迟 2-5 秒
- 网络快：延迟 0-100ms
- 服务不稳定：30% 概率返回错误
- 自定义场景：自己设置延迟、错误率、超时等

### 5. 接口测试
- 内置的 HTTP 测试工具
- 可以直接在后台测试接口，看返回结果

## 常见问题

### Q: 为什么必须用 Cursor？

A: 因为本项目的核心是"AI 自动生成接口"，需要 Cursor 的 AI 能力来读取项目规则和模板。如果不用 Cursor，就要手写代码了，那就失去了这个工具的意义。

### Q: 生成的接口代码需要版本控制吗？

A: **不需要**。`src/generated/` 目录已经加入 `.gitignore`，生成的代码不会被提交。因为这些接口本来就是临时用的，后端开发完成后就没用了。

### Q: 可以手动删除 `src/generated/` 下的文件夹吗？

A: **不建议**。虽然技术上可以，但可能会有数据库表残留。正确做法是用后台管理页面的"删除模块"功能，会自动清理数据库。

### Q: 生成的接口不符合预期怎么办？

A: 继续在 Cursor 聊天框里告诉 AI 修改，比如："把用户列表接口的分页参数改成 page 和 size"。AI 会自动修改代码。

### Q: 能同时生成多个模块吗？

A: 可以。每个模块都是独立的，互不影响。你可以生成 users、products、orders 等多个模块。

### Q: 切换到真实后端接口后，这个项目还有用吗？

A: 看情况。如果后端接口稳定了，这个项目就可以不用了。但如果需要：
- 模拟各种异常场景（网络慢、接口报错等）
- 快速测试新功能（后端还没开发）
- 演示 Demo（不依赖真实后端）

那还是有用的。

### Q: 数据会丢失吗？

A: 数据存在 MySQL 里，只要不清空数据库，数据就在。但记住这些都是测试数据，不是生产数据。


## 项目结构（简化版）

```
node-api-server/
├── src/
│   ├── generated/              # AI 生成的接口（不会提交到 git）
│   │   ├── users/             # 用户模块
│   │   ├── products/          # 商品模块
│   │   └── ...                # 其他模块
│   ├── template/              # 接口模板（AI 参考这个生成代码）
│   ├── system/                # 系统功能（后台管理 API）
│   └── ...
├── public/admin/              # 管理后台前端
├── .cursor/rules/             # AI 规则文档
└── .env                       # 数据库配置
```

**重点**：
- `src/generated/` - 所有生成的接口都在这里，可以随时删除
- `src/template/` - AI 生成代码的模板，不要改
- `.cursor/rules/ai-rules.md` - AI 的行为规则，不要改
